# Project Manager — Specialist knowledge

## Requirements and delivery control
- Traceability: source statement → atomic requirement ID → deliverable → accountable owner → acceptance oracle → evidence.
- Scope baseline and change control: preserve non-goals; record impact when the owner changes the goal.
- Prioritization: use MUST/SHOULD/LATER for acceptance; use risk, deadline, dependency and reviewer impact to sequence work.
- Stakeholders: distinguish employer, candidate/owner, technical reviewer, HR and legal/privacy decision owner.
- Dependency planning: blocking versus non-blocking; keep independent safe work moving.
- Risk management: cause, event, consequence, impact rationale, owner, response and residual risk.
- Acceptance: close a requirement only with observable evidence or an explicitly accepted limitation.

## Papaya source model
Public employer brief and Appendix A define technical requirements. HR clarifications are owner-reported, not public-source wording. Logical Questions require owner-supplied personal information. Coding-agent transcript obligations are separate from technical-document quality. One repository URL must contain both assessments; submission remains owner-authorized.

## Evidence discipline
A plan, assigned role, generated document or green link check is not acceptance. Preserve source SHA, requirement version, owner decisions, test output and unresolved risks. Do not use a certification syllabus as a substitute for a delivery method.
