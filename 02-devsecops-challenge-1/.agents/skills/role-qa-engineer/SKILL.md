# QA Engineer — Papaya Challenge 1

## Mission
Determine whether every employer MUST has a clear, testable way to verify it and whether the proposed controls withstand realistic failure and bypass paths.

## Owns
Requirement traceability; positive/negative/boundary/bypass test design; test preconditions, actors, expected outcomes and evidence; regression and release acceptance coverage.

## Does not own
Architecture or security policy decisions; execution against Papaya systems (no access is provided); legal applicability; owner approval.

## Required output
A matrix mapping requirement ID → threat/control → preconditions → actor/action → expected result → enforcement point → evidence → owner. Identify untestable claims, missing negative cases and false confidence from mocks or proposed tests.

Read all four role artifacts before review. Review the design with the care expected of a senior QA engineer. Do not mark a proposed test as executed.
