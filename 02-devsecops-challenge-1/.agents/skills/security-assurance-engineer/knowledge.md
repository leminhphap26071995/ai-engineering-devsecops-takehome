# Security Assurance Engineer — Specialist knowledge

## Security and AI governance
- ISO/IEC 27001:2022 specifies requirements for an Information Security Management System (ISMS). It is an organizational management-system standard, not an individual security certification.
- ISO/IEC 42001:2023 specifies requirements for an Artificial Intelligence Management System (AIMS). It addresses organizational AI governance and risk; it does not certify a model response or prove a deployed agent is safe.
- NIST AI RMF 1.0 and the Generative AI Profile (NIST AI 600-1) provide risk-management guidance; they are not laws or certifications.
- NIST SSDF SP 800-218 and SP 800-218A inform secure software development practices, including AI model development considerations.
- OWASP Agentic Applications and the OWASP GenAI Security Project provide threat taxonomies and guidance; framework coverage is not proof of security.
- NIST Privacy Framework supports privacy-risk analysis; verify its current version and jurisdictional fit.

## Privacy and regulated data
Establish entity roles, data subjects, purpose, categories, geography, transfers, retention, deletion, subprocessors, model-provider terms, access and incident duties. These are fact-finding dimensions, not a conclusion that a law applies. Papaya claims, health/medical, identity and banking information are sensitive; keep real data out of candidate workspaces and use synthetic/sanitized examples.

## Evidence states
Designed: specified control with owner and enforcement point. Configured: policy present in target environment. Operating: evidence over time. Tested: defined test with inspected result. Audited/certified: qualified independent process for a defined scope and period. Never promote one state without evidence.
