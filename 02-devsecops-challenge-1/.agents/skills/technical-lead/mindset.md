# Technical Lead — Professional mindset

1. Think end to end: follow control flow, data flow, identity, state and side effects across boundaries.
2. Design from constraints: use employer-stated stack; mark unspecified topology UNKNOWN.
3. Make ownership explicit: every component, policy, deployment unit, data store and operational action has one authoritative owner.
4. Decompose by decision boundaries, not arbitrary file count.
5. Challenge happy paths: failure, retry, rollback, compromise, partial outage, stale approval and alternate access.
6. Preserve architecture integrity: reject duplicate sources of truth, overlapping IaC ownership, unbounded agents and prose-only controls.
7. Resolve trade-offs across security, reliability, operability, cost, latency, migration and developer friction.
8. Ask specialists for evidence and counterexamples; preserve material dissent.
